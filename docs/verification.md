# 사용자 웹 검증

검증일: 2026-09-30. 초기 가상 신원 검증, 실제 학교 로그인 UI 연결, 운영 HTTPS 확인을 순서대로 기록합니다. 각 단계의 검증 범위는 구분합니다.

## 초기 개발 환경 검증

이 절은 가상 신원을 사용하는 비공개 개발 환경에서 실행한 결과이며 실제 학교 인증·회원 명부·운영 Minecraft 접속 검증을 의미하지 않습니다.

- Node.js 24에서 `npm ci`, TypeScript 검사와 Vite production build
- 설치 시 npm audit 취약점 0건
- 실제 API와 PostgreSQL에 연결한 개발 회원 로그인, 프로필·허용 서버 조회
- Discord 숫자 ID 저장 → 새로고침 후 값 유지
- uint64 범위를 넘는 ID 입력 거부 → 기존 저장값 유지
- Discord ID 삭제 → 새로고침 후 삭제 유지
- 로그아웃 → 입력 폼 비활성화
- 미등록 가상 회원 → 명부 미등록 표시, 허용 서버 없음
- 토큰이 없는 Minecraft 연결 URL → 새 링크 안내
- 같은 브라우저에서 관리자 화면 접근 차단 및 사용자 세션 유지
- 데스크톱 1280px, 모바일 390px에서 화면 표시와 가로 넘침 없음
- 브라우저 런타임 오류 및 Vite 오류 화면 없음
- 배포 HTML의 CSP, Referrer-Policy, X-Frame-Options, nosniff, no-store 확인

## 초기 단계 당시 남은 검증

- 실제 Minecraft 클라이언트와 함께 웹 확인·게임 확인·서버 이동을 끝까지 수행

검증 도중 이전 저장 성공 안내가 잘못된 새 입력의 오류와 함께 남는 문제를 발견하여 새 제출 시 안내를 지우도록 수정했습니다. 수정 후 TypeScript 및 production build를 다시 통과했습니다.

## ALMS v4 A · Pretendard 변경 후 재검증

2026-09-30, 새 UI를 실제 개발 API와 연결한 배포에서 재검증했습니다. 화면 내용은 Passport 기능에 맞게 구성하고 사용자 요청으로 글꼴만 Pretendard로 변경했습니다.

| 로그인 카드 | 410 × 432.95px, 원본 카드 약 434px 높이와 대응 |
| 앱 사이드바 / 상단 바 / 개발 표시 | 216px / 64px / 28px |
| 카드 안쪽 여백 / 반경 | 20px / 12px |
| 주 동작 색 | `rgb(27, 100, 218)` = `#1B64DA` |
| 선택 메뉴 배경 / 글자 | `#F2F4F6` / `#191F28` |
| Pretendard 가변 폰트 | `document.fonts` status `loaded`, weight `100 900` |

Figma v4 A 로그인·대시보드 렌더와 색상·레이아웃·카드·내비게이션·간격을 비교했습니다. 원래의 녹색 장식 요소는 제거했습니다. 로그인, 대시보드, Discord 입력 화면, 모바일 화면을 직접 확인했습니다.

회원 로그인 → Discord 메뉴 이동 → ID 저장 → uint64 초과 입력 거부 → 이전 성공 안내 제거 → ID 삭제 → 새로고침 후 삭제 유지 → 모바일 로그아웃을 실제 API로 확인했습니다. 미등록 회원은 허용 서버 없음으로 표시되며, 토큰 없는 연결 URL은 새 링크 안내를 표시합니다. 브라우저 런타임 오류는 없었습니다.

## 실제 학교 로그인 UI 연결 검증

2026-09-30, `university` 모드 연결을 구현하고 로컬 브라우저에서 API 계약 응답을 주입해 확인했습니다. 아래 기록은 실제 학생의 인증 성공이나 명부 일치를 주장하지 않습니다.

- `npm run check`: TypeScript와 6개 로그인 URL·오류 메시지·접속 상태 테스트 통과
- `npm run build`: Vite production build 통과
- 학교 로그인 버튼 → 실제 `smartid.ssu.ac.kr/Symtra_sso/smln.asp` 이동 → 학교의 비밀번호 입력 폼과 `smln_pcs.asp` action 확인. 학교 계정은 입력하지 않음
- 콜백 오류 query를 최초 로드 때 제거하면서 만료 안내를 표시하고 다시 로그인 가능
- Minecraft 링크의 ID·토큰과 CSRF가 로그인 시작 POST로 전달됨. URL fragment 제거 및 localStorage/sessionStorage 비어 있음 확인
- API 응답을 외부 호스트 URL로 바꾼 계약 테스트에서 이동 거절
- 재학·휴학·알 수 없는 학교 학적 라벨 모두 회원 명부가 활성인 경우 같은 회원 표시 사용
- 서버의 만료·취소·정지 결과를 브라우저 시간과 별개로 우선 반영
- 1440×900 및 390×844에서 개발 띠·가상 문구 없음, 가로 넘침 없음, Pretendard 실제 로드. 데스크톱 사이드바 216px·상단 바 64px 유지
- 브라우저 런타임 오류 없음

이 단계에서는 학교 로그인 입력과 콜백 완료를 수행하지 않았습니다. 이후 실제 인증 확인 범위는 아래에 기록합니다. 학교 토큰·비밀번호·개인 학적 화면은 브라우저 검증 파일이나 저장소에 보관하지 않습니다.

## 운영 HTTPS와 실제 학교 로그인 확인

별도 익명 브라우저에서 운영 HTTPS 사용자 포털을 확인했습니다. 사용자의 로그인된 브라우저와 쿠키를 공유하지 않았습니다.

- 1440×900 및 390×844에서 로그인 화면 정상 표시, 빈 화면·오류 오버레이·가로 넘침·JavaScript 오류 없음
- 실제 세션 API HTTP 200, 익명 상태와 `university` 모드 확인
- 실제 학교 로그인 시작 API HTTP 200, 지정된 HTTPS SmartID 호스트·경로와 사용자 포털로 돌아오는 콜백 경로 확인
- 리다이렉트 URL의 사용자명·비밀번호·fragment 없음 확인. nonce·학교 토큰은 출력하거나 저장하지 않음
- Pretendard `loaded`, 폰트 HTTP 200·2,057,688바이트, 주 동작 색 `#1B64DA`
- 토큰 없는 연결 링크의 재발급 안내, 만료 콜백의 안내와 query 제거 확인

별도로 사용자가 직접 실제 학교 로그인을 완료했습니다. 배포 담당자는 서버 집계로 `usaint` 신원 1건과 활성 명부 일치 1건을 확인했습니다. 이 확인은 실제 학교 인증 콜백과 명부 대조 성공의 근거이며, 학번·이름·학교 토큰 원문은 이 문서나 테스트 파일에 포함하지 않습니다. 실제 Minecraft 연결·게임 이동 또는 관리자 MFA까지 완료했다는 의미는 아닙니다.

## 세션 만료 회귀 검증

8시간 세션 만료 뒤 변경 요청이 401로 거부되면 이전 회원 화면이 남는 문제를 수정했습니다. 회원·서버·Discord·연결 정보와 이전 CSRF를 제거한 뒤 새 익명 세션을 조회합니다.

`npm run test:browser-session`은 production build를 만든 뒤 루프백 합성 API와 격리된 실제 브라우저로 다음 두 경로를 검증합니다. 운영 API·학교 로그인·실회원은 사용하지 않습니다.

- Discord 저장 요청의 401 → 이전 개인 정보 제거 → 로그인 버튼과 만료 안내
- 로그아웃 요청의 401 → 동일한 상태 제거와 익명 화면 복귀
- 두 경로 모두 새 세션 조회, 재로그인 요청에 새 CSRF 사용, 브라우저 저장소 비어 있음, 런타임 오류 없음

두 시나리오를 포함한 3개 테스트 그룹, 기존 인증 도우미 테스트 6건, TypeScript 검사와 production build를 통과했습니다. 브라우저 테스트는 `agent-browser@0.38.1`과 실행 가능한 Chrome이 필요합니다.

## 아직 확인할 범위

실제 Minecraft 클라이언트의 웹·게임 양쪽 확인, 서버 이동, 실시간 권한 회수와 회원 복구 절차는 별도로 확인해야 합니다. 실제 학교 로그인 1건의 성공이 모든 학적 상태나 이후 학교 페이지 변경에 대한 파서 호환성을 보장하지는 않습니다.
