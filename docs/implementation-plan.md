# 사용자 웹 구현 계획

## 연결 흐름

1. 정품 Java 계정으로 접속한 사용자가 Velocity에서 개인별 일회용 URL을 받습니다.
2. 웹은 URL에 담긴 연결 요청을 API에 전달하고 만료 여부를 확인합니다. URL을 열었다는 사실만으로 계정을 연결하지 않습니다.
3. API가 학교 SSO 흐름과 학적 검증을 수행합니다. 프론트는 성공·실패·재시도 상태를 표시합니다.
4. 사용자는 연결될 Minecraft 계정을 웹에서 확인합니다. API 상태는 `게임 확인 대기`가 됩니다.
5. 같은 정품 Minecraft 계정에서 `/passport confirm`을 실행한 뒤 API가 연결을 확정합니다.
6. 웹은 확정된 회원 상태와 서버별 접속 권한을 표시합니다.

학교 SSO의 서비스 콜백 허용 여부와 반환값 검증 방식은 API PoC로 확인해야 합니다. 이 문서는 학교 로그인 연동이 이미 가능하다는 검증 결과가 아닙니다.

## 화면 범위

| 화면 | 표시할 정보와 동작 |
| --- | --- |
| 연결 시작 | 대상 Minecraft 계정, 만료 상태, 학교 인증 버튼 |
| 연결 확인 | 학교에서 확인한 최소 정보, 대상 계정 확인, 게임 내 확인 안내 |
| 내 계정 | 회원 자격, 연결 상태, Discord ID, 허용 서버 |
| Discord ID 입력 | 숫자 ID 입력·수정·삭제, 소유권 미확인 표시 |
| 오류·대기 | 만료, 이미 연결됨, 명부 미등록, 정지, 외부 서비스 장애 |

## 인증·데이터 경계

- HttpOnly 세션을 사용하고 API 변경 요청에 CSRF 방어를 적용합니다.
- 로그인 세션이나 학교 토큰을 localStorage에 저장하지 않습니다.
- 일회용 URL에 포함된 비밀값이 리퍼러·분석 로그에 남지 않도록 하고, 링크 확인 후 주소에서 제거하는 흐름을 API와 합의합니다.
- Discord ID는 JavaScript `number`로 변환하지 않습니다. 서버가 형식을 검사하고 `self_reported` 상태로 저장합니다.
- Discord ID 입력은 본인 Discord 계정을 증명하지 않습니다. 이를 로그인 수단, 역할 부여 근거, 서버 접근 권한 근거로 사용하지 않습니다.
- 사용자가 제출한 학번·권한 값은 신뢰하지 않습니다. 최종 상태는 API 응답에서만 가져옵니다.
- 학교 검증과 회원 명부 매칭은 별도 결과로 표현합니다.

## 구현 완료 조건

- 웹 최종 확인만으로 Minecraft 연결이 활성화되지 않습니다.
- 만료되거나 이미 사용한 링크는 재사용할 수 없습니다.
- 명부 미등록자에게 회원 서버 접근 가능 상태를 표시하지 않습니다.
- Discord ID 입력만으로 인증 완료·소유권 확인 표시가 나오지 않습니다.
- 실제 API와의 세션·CSRF·오류 처리를 확인한 뒤 실행 가능 상태로 문서를 갱신합니다.

현재는 설계 문서만 있으며 위 조건은 향후 검증 대상입니다.
